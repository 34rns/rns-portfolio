# Rollback

Keep the prior production deployment ID, canonical URL, schema journal and encrypted backup in private release evidence. Return traffic to that deployment if the new release fails; retain the additive tables and all new redemptions. Never drop the tables or restore an older database over customer activity created after release.

Disable new staff mode only with the configured original owner preserved. Keep encryption keys unchanged and retain old public verification keys until all tokens they signed reach their offline deadline. Returning traffic to another origin does not repair mismatched token issuers; preserve the origin/callback transition manifest.

Pause background delivery before changing its host; the transactional outbox and leased deliveries can resume on one verified runner. Keep old Blob assets and model references until the new storage has passed upload/read/delete checks. Do not remove the previous host/storage during the first verified release.
