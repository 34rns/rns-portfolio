# Contributing to the licensing module

Use synthetic local PostgreSQL with `npm run licensing:demo`; tests create separate databases and apply additive migrations there. Never source `.env.local` for migrations, restore or seed checks. It may point to production.

Preserve the public portfolio, legacy APIs and customer records. Keep app/environment scope at every service boundary and load current staff permissions for each action. Put server commands in the shared command layer so HTTP and the admin UI agree. Use real PostgreSQL tests for locking/rollback and a real browser for user flows. A visible button must have a working permission-checked action.

Run the release checklist before claiming completion. Add a small behavioral regression for security/money/concurrency logic; avoid tests that simply match source text. Review SDK target evidence independently of shared fixtures. No paid services, push or public release without owner authorization.

The export is a safe integration kit for the central service. A new standalone backend would require its own tested setup; do not label this kit a deployable independent server. No new open-source license has been granted without ownership review.
